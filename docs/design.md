# V1.0 系统设计

## 硬件分工

泰山派 RK3566 运行 Linux 应用，负责 V4L2 采集、RKNN 推理、坐标下发、本地预览及 RTSP。MSPM0G3507 负责坐标接收、PID、模式状态机与 Emm V5 驱动器通信。

UART1 接收视觉坐标，UART0 对接电机驱动器，两路均为 115200。PB6 用于控制模式切换。

## 数据与线程

采集、推理及串口发送通过 LatestSlot 交换最新数据。单槽覆盖避免慢消费者形成不断增长的视频队列。推理结果保存对应原图，预览不会将旧检测框叠加到不同图像。

每个有效推理结果仅发送一次，避免主控将重复结果作为新测量参与积分与到位计数。默认无目标时静默，可显式配置无效坐标停机策略。

图传可共享识别摄像头，也可使用独立摄像头。第二摄像头或 RTSP 启动失败只停止图传；识别采集、推理或串口关键线程失败会退出应用并清理资源。

## 控制模式

- 定点序列：依次到达 325、565，连续满足容差后切换，最终保持末目标。
- 小车补偿：目标为 400，内部阶段状态机提供加速、匀速、减速与停止阶段的补偿。

控制参数集中于 app_settings.h。PID 使用标称 dt，实际循环还包含驱动器应答和遥测等待；阶段计时不是底盘反馈。

## 模型与显示

检测器输入源图 BGR，内部完成 ROI、letterbox、RGB / uint8 / NHWC 输入准备。默认后处理要求 6 或 9 个 Rockchip YOLOv8 DFL 输出，替换模型时需核对契约。

模型权重独立提供。未配置模型时正常模式报错，预览模式仍可检查摄像头和图传。
